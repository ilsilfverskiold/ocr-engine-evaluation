### Confirmed defects in our evaluation or collection

1. **Wrong primary evidence in the report.** The shared excerpt template
   displayed `raw_text` for every leg. Geometry must display the actual boxes
   on the exact input image; KV must display FORMS/JSON pairs. The renderer's
   geometry overlay did use stored boxes, but the transcription above it did
   not explain the score. The corrected export's SVG coordinates and counts
   were checked against the source calls, and its KV table against the scorer
   input. Report presentation and score validity are separate checks.
2. **Default prompts were sent but not persisted.** Gemini lease_000 received
   its runner's transcription prompt. Five headings were found as plain text
   or list items: 8/13 correct, 5 wrong_type. STOP, not truncation. Adding only
   heading markers makes a diagnostic 13/13; that is not a measured rerun.
   Claude/Gemini Markdown and table comparisons still need the dedicated
   asks now present in the registry. Future prompt logging is repaired.
3. **Primitive-array positions could borrow another column's value.**
   `columns[0]` could match `columns[1]`, and `rows[0].values[0]` could match
   `rows[0].values[1]`: swapped values earned full credit. Fixed in field
   scorer v5. Object-array rows may still align; their cells retain their
   column identity. Also fixed: an explicitly returned schema path with a
   wrong value could borrow the right value from a sibling with the same
   leaf name. These are false positives, not reasons to raise a poor score.
4. **RM currency formatting was penalized.** `408.45` versus `RM408.45`
   is the same printed amount on photo_001. The v4 checker called it wrong
   for Claude, Gemini and Textract KV. v5 recognizes the currency prefix;
   it still rejects wrong digits and amounts embedded in unrelated prose.
5. **Qwen geometry fallback dropped recoverable objects.** A malformed or
   truncated response defeated the capture adapter. The scorer's fallback
   knew `text`/`bbox` but not Qwen's `text_content`/`bbox_2d`. It now salvages
   complete valid objects without inventing the unfinished ones. This
   repairs an adapter loss; it does not make the remaining coordinates
   accurate or recover words the model never returned.
6. **The reference violates the supplied schema on 19 pages, in 207 places.**
   All validation errors are GT nulls prohibited by the schema: 178 number,
   22 string, five array and two object fields. A constrained extraction
   interface cannot satisfy both that schema and our blank-field GT.
   Pages: medical_000/001/003/004; all five payslips;
   photo_000/002/003/004; shipping_000/001; tax_000/001/002/003.
   This does not affect engines equally: provider-enforced schema output,
   prompt-only JSON and GLM's empty-example interface impose different
   constraints. Repair and validate the schemas before rerunning those tasks;
   do not silently credit invented zeros as blanks.
7. **Open-ended schemas do not prescribe the names the scorer demands.**
   funsd_001 supplies only an object with additional string/null properties,
   while the checker expects specific GT names. The saved LlamaExtract job reports SUCCESS with `data={}` and an effective
   schema of `properties={}`, `required=[]`, `additionalProperties=false`: it
   was effectively asked to return an empty object. Claude returned differently
   named fields. Financial tables allow arbitrary
   `values` keys while the reference mixes date keys with `col_3`/`col_4`.
   These are task/reference contract defects, not established model inability.
   The saved LlamaExtract effective schemas confirm this on eight pages:
   funsd_001 and funsd_005 have closed empty root objects; all five fintabs
   have closed empty `rows[].values`; funsd_004 has a closed empty `# CASES`
   object. Every job reports SUCCESS. Specify the intended fields/columns,
   audit the reference against the page,
   and rerun with the corrected schema. The current self-consistency test
   (GT scored against itself) does not detect either defect.
