### What counts as a correct cell

Match tables, rows and columns by their relationships, including labels and
headers, rather than searching for values anywhere in the output. A cell earns
credit only when its content and association are correct. Reordered columns
can be equivalent if their headings and values remain associated; a price
under Quantity is wrong. Accept supported Markdown, HTML and native table
representations through deterministic parsing.

Use **one-to-one matching**: each reference cell and output cell can participate
in at most one match. If the gold contains `100` in three distinct positions,
one returned `100` cannot satisfy all three. Apply the same constraint when
matching tables and rows so duplicated output cannot reuse a reference table
or row for credit. Alignment should establish correspondence before deciding
whether the cell value is correct, so a wrong value is not merely hidden by
rematching it elsewhere.

### Count blanks, omissions, wrong values and extras

- A real empty cell in the gold is an expected cell. A corresponding empty
  output cell earns credit; an invented value in it is wrong. A missing cell
  or missing row is not a correctly preserved blank.
- Positions covered by a merged cell are not additional empty cells. Count
  the logical merged cell once, retaining its span for structural evaluation.
- Padding introduced by our parser is not an output cell and must not earn
  blank credit or incur an extra-cell penalty.
- Missing expected cells reduce recall. Unmatched extra cells, including
  cells in duplicated rows or tables, reduce precision. Repeated values that
  genuinely occur in separate gold cells are not themselves duplicates.
- An aligned cell with a wrong value, including an incorrectly filled blank,
  contributes no correct match: it is both an unsatisfied reference cell and
  an incorrect output cell. Mere appearance in plain text earns no table-cell
  credit.

Let `C` be correctly matched cell pairs, `R` the number of eligible reference
cells, and `P` the number of eligible output cells, including actual blanks:

- **Recall = C / R:** how much of the reference the engine got right.
- **Precision = C / P:** how much of the returned table content is correct.
- **Cell F1 = 2C / (R + P):** the main score, penalizing omissions and extras.

For a page with expected cells but no returned table, recall and F1 are zero;
report precision as N/A because there are no predicted cells. Pages without a
table reference retain the benchmark's separate eligibility handling.

| Example, with 10 expected cells | Recall | Precision | Cell F1 |
|---|---:|---:|---:|
| All 10 correct | 100% | 100% | 100% |
| 8 correct, 2 missing | 80% | 100% | 88.9% |
| All 10 correct, plus 5 duplicate cells | 100% | 66.7% | 80% |
| 8 correct, 2 incorrect values | 80% | 80% | 80% |
