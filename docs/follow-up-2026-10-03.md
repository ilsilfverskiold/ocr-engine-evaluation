### KV value containment and contextual judge correction — 2026-10-07

**User's actual rule:** check whether returned values occur inside reference
values (or vice versa). Use that overlap to build judge items. The judge decides
whether the keys and complete value are correct, including split values. Do not
replace this with Seller/Client-specific logic or automatic prefix-based credit.
Both deterministic split-credit attempts are withdrawn; their scores are not
current benchmark results. No ambiguous-amount occurrence-credit rule is active.

Implementation `shared-fields-v5-judged-value-groups` uses the common KV evaluator
for every engine, live runs, saved scoring and rescoring:

- Reuse valid known keys and cached positive synonyms/confirmed pairs first.
- For remaining fields, find full-value matches and whole-token containment in
  both directions. Normalize leading/trailing currency glyphs for amounts;
  preserve numeric boundaries, signs, decimals and identifier digits. Overlap
  only nominates a candidate and never earns credit.
- Build reference-centered judge items containing candidate output IDs. Supply
  all returned keys/values as context, including empty parents and neighboring
  fields. The judge can select multiple fragments for one complete value.
- Validate complete coverage and forbid reuse of an output across fields.
  No Name/Address/City whitelist, required key prefix, document-name or engine-
  specific condition exists. An empty parent may be repaired by judge-confirmed
  fragments. A nonempty contradictory known answer is not silently replaced.
- Rebuild old negative decisions when the request now includes partial values
  or previously omitted returned context. Old positives remain reused. Cache
  group approvals/rejections against the entire returned-pair context and gold
  identity. Promote a single key to a reusable synonym only when the judge
  explicitly approves that and complete-value comparison passes.
- Show selected keys, actual values, judge reason and request ID. Without a
  required new decision, show pending and a provisional calculation, not a
  completed benchmark score. Never claim “no search by value.”

## Latest KV decision — inline value-assisted evaluation

$5 full replacement plan.** Match known keys first during evaluation. Only if
no key matches, check the returned value for complete reference-value candidates
and send the unresolved pair to the judge. Cache confirmed wording as evaluation
proceeds; future engines use the same evaluator and cache. No value candidate,
known key or cached mapping means no new judge call. Equal values do not alone
establish identity; judge confirmation is required.

wording-only synonym is reusable on this page, while its value is always checked
again. Contradictory known keys cannot be remapped by finding their value under

edits invalidate decisions. All selected schema fields also participate in KV;
the obsolete scalar-only/printed-pair/minimum-three eligibility rules are removed.
