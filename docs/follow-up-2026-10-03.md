### What counts as a correct cell

Match tables, rows and columns by their relationships, including labels and
headers, rather than searching for values anywhere in the output. A cell earns
credit only when its content and association are correct. Reordered columns
can be equivalent if their headings and values remain associated; a price
under Quantity is wrong. Accept supported Markdown, HTML and native table
representations through deterministic parsing.

Use **one-to-one matching**: each reference cell and output cell can participate
in at most one match. If the gold contains `100` in three distinct positions,
one returned `100` cannot satisfy all three. Apply the same constraint when
matching tables and rows so duplicated output cannot reuse a reference table
or row for credit. Alignment should establish correspondence before deciding
whether the cell value is correct, so a wrong value is not merely hidden by
rematching it elsewhere.

### Count blanks, omissions, wrong values and extras

- A real empty cell in the gold is an expected cell. A corresponding empty
  output cell earns credit; an invented value in it is wrong. A missing cell
  or missing row is not a correctly preserved blank.
- Positions covered by a merged cell are not additional empty cells. Count
  the logical merged cell once, retaining its span for structural evaluation.
- Padding introduced by our parser is not an output cell and must not earn
  blank credit or incur an extra-cell penalty.
- Missing expected cells reduce recall. Unmatched extra cells, including
  cells in duplicated rows or tables, reduce precision. Repeated values that
  genuinely occur in separate gold cells are not themselves duplicates.
- An aligned cell with a wrong value, including an incorrectly filled blank,
  contributes no correct match: it is both an unsatisfied reference cell and
  an incorrect output cell. Mere appearance in plain text earns no table-cell
  credit.

Let `C` be correctly matched cell pairs, `R` the number of eligible reference
cells, and `P` the number of eligible output cells, including actual blanks:

- **Recall = C / R:** how much of the reference the engine got right.
- **Precision = C / P:** how much of the returned table content is correct.
- **Cell F1 = 2C / (R + P):** the main score, penalizing omissions and extras.

For a page with expected cells but no returned table, recall and F1 are zero;
report precision as N/A because there are no predicted cells. Pages without a
table reference retain the benchmark's separate eligibility handling.

| Example, with 10 expected cells | Recall | Precision | Cell F1 |
|---|---:|---:|---:|
| All 10 correct | 100% | 100% | 100% |
| 8 correct, 2 missing | 80% | 100% | 88.9% |
| All 10 correct, plus 5 duplicate cells | 100% | 66.7% | 80% |
| 8 correct, 2 incorrect values | 80% | 80% | 80% |

## 4. Keep text scoring and report evidence clear

The user explicitly wants **CER and WER included in text evaluation now**.
Both already exist in saved text results and the per-page viewer. Make them
visible alongside coverage in engine-level comparisons as well.

| Measure | Plain-language meaning | Direction |
|---|---|---|
| Coverage | How many distinct reference words were found anywhere | Higher is better |
| CER | How much the letters, digits and other characters differ from the reference | Lower is better; zero is a normalized match |
| WER | How much the sequence of whole words differs from the reference | Lower is better; zero is a normalized match |

CER/WER count missing, extra and substituted characters/words. Correct text
in a different order also increases them. They do not directly tell us the
percentage of characters/words visually misread. Our normalization strips
Markdown/HTML, decodes entities, collapses whitespace and lowercases text;
these rates therefore do not measure heading syntax or spacing-entity bloat.
Incomplete/incorrect GT also affects them. Error rates can exceed 100% when
there are many extra characters/words; do not clamp or call 100 minus the
rate a bounded accuracy percentage.

Actual saved Sonnet examples: invoice_000 has coverage 100%, CER 26.36% and
WER 28.74%; bank_001 has coverage 99.65%, CER 0.37% and WER 2.75%. The invoice's
interleaved seller/client ordering contributes to the difference despite
complete distinct-token coverage.

**Recommendation, not an agreed scoring-policy change:** do not average CER
and WER into a single score. They count overlapping errors at different scales;
one wrong digit can be one character error but an entire word error. A blend
adds arbitrary weights and still cannot distinguish recognition from order
or reference defects. Present a compact `Coverage | CER ↓ | WER ↓` comparison.
If a single default sort is needed, choose and label one measure explicitly
rather than inventing a combined accuracy score; keep the other columns visible.

processed, with explicit coordinate order; normalize afterward in code. Prepare
the image before sending it so automatic resizing does not change that frame.
Standard image limits account for both the long edge and patch budget, not
only width/height. Cropping can help with small targets, but spatial estimates
remain approximate. Put the image before its instructions. Sources:
[coordinate guidance](https://platform.claude.com/docs/en/build-with-claude/vision-coordinates)
and [vision guidance](https://platform.claude.com/docs/en/build-with-claude/vision).

Proposed tighter wording, retaining `claude-sonnet-4-6`:

```text
Locate every visible word in this image. Return only a JSON array of objects:
{"text": "the printed word", "bbox": [left, top, right, bottom]}.
The supplied image is {width} pixels wide and {height} pixels high.
Coordinates are absolute pixels in this supplied image, with (0, 0) at the
top left, x increasing rightward and y increasing downward.
Give one tight rectangle around each word at its actual printed location.
Keep punctuation attached to its word. Do not combine words into line boxes.
Do not reconstruct a cleaner layout or infer positions from reading order.
Include visible headers, footers and table text. Return no Markdown or prose.
```
